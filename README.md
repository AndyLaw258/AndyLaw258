#### 🔍 [ctxgc](https://github.com/AndyLaw258/ctxgc) · 审计 AI Agent 的上下文成本

所有 token 统计工具都算体积；它算的是 **`体积 × 存续轮数`**。

换到这个维度之后，结论会翻转。实测一条真实会话：

| 类别 | 体积 | 累计读取 | 放大 |
|---|---|---|---|
| **助手输出** | 140.0k | **6.73M** | 48x |
| 工具结果 | 65.1k | 4.91M | 75x |
| **合计** | 214.2k | **12.59M** | **58.8x** |

按体积排，工具结果是最大来源；**按生命周期排，模型自己的输出反超**。

- **精确归因** —— 建立在运行时上报的用量上，不是字符估算
- **反事实模拟** —— 用真实调用序列重放另一种上下文策略
- **自带可信度证明** —— 报告里打印对账偏差（实测 ±0.0%），三组不变式交叉验证
- **零第三方依赖** · 94 项测试 · 也能审计 DSH 之外的运行时

#### 🩺 [dsh-firstrun-doctor](https://github.com/AndyLaw258/dsh-firstrun-doctor) · DSH 环境自检插件

输入链故障的**归因**，加上一个常驻的日志格式哨兵。

难点不在检测，在**不冤枉好人** —— "光标跳回第一行"至少有四个嫌疑人：翻译扩展、输入法、键盘重映射工具、编辑器自身缺陷。

四层职责分离：客户端只采证据、宿主提供机器真相、规则是纯函数、语言锁管提示词注入。九条规则每条都有**敏感度与特异性的双向测试**，**证据不足时明确说"不知道"**。

README 里记着 **9 个"测试全绿但真跑才暴露"的缺陷** —— 那部分比功能更能说明我怎么工作。

#### 我怎么做事

| 原则 | 具体表现 |
|---|---|
| **先测量，再断言** | 两个项目都是"审计 → 模拟 → 才给建议"，并且各自有一份写在 README 里的**诚实清单** |
| **假阳性比漏报更伤** | 一个总在喊狼来了的工具会被学会忽略 —— 那比没有工具更糟 |
| **静默失败最贵** | 一个会崩的工具你立刻知道它坏了；一个数字偏低的工具你会照着它做决策 |
| **知道在哪里不说话** | 有些情况证据不足以判定，那就如实说不知道，而不是给一个看起来有用的结论 |

> 两个项目都不承诺"帮你省钱"。它们是仪表盘，不是发动机 —— 但能让"钱花在哪"从猜测变成可测量的事。
